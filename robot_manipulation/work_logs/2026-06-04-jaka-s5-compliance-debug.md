# 2026-06-04 JAKA S5 柔顺调试工作日志

## 目标

验证 `JAKA S5` 在 Python SDK 下的力控 / 柔顺能力，期望达到以下测试效果：

- 运行脚本后，机械臂进入可手推的柔顺状态。
- 人手甚至双手阻挡机械臂时，机械臂应柔顺响应，而不是闪红灯或立即报警停机。

## 今日调整内容

- 放弃早期堆叠过多逻辑的长脚本，重写为最小化测试脚本：`scripts/jaka_admittance_motion_trial.py`。
- 修正力传感读取调用，避免 Python 绑定参数类型错误。
- 区分并同时打印两类力传感数据：
  - `raw(type=2)`：原始传感器读数。
  - `external(type=3)`：补偿 / 置零后的外力读数。
- 新增末端负载自动辨识流程：
  - `start_torq_sensor_payload_identify(...)`
  - 轮询 `get_torq_sensor_identify_staus()`
  - 读取 `get_torq_sensor_payload_identify_result()`
  - 写回 `set_torq_sensor_tool_payload(...)` 与 `set_payload(...)`
- 将辨识结果保存到本地：`JAKA_control/config/jaka_s5_orcahand_payload.json`。
- 新增 payload 缓存复用逻辑：本地有完整参数时，后续运行默认跳过重新辨识，直接加载并写回控制器；仅在显式传 `--force-payload-identify` 时重辨识。
- 在进入柔顺前执行 `zero_end_sensor()`，并保留 `set_compliant_type(1, 0)` 的官方初始化流程。
- 触发方式从“实际位移运动”收缩为“`linear_move(ABS)` 到当前位置”，尽量按官方文档最小路径验证恒力柔顺。

## 已确认结果

### 1. payload 辨识链路可跑通

真机已成功完成 payload 辨识，并得到可写回控制器的质量与质心参数。脚本也已能兼容 Python 绑定返回的扁平结果格式。

### 2. 置零 / 补偿并非完全失效

一度怀疑 `fz` 持续约 `-16 N` 说明置零失败，但后续确认此前看的主要是 `raw(type=2)`。

真机后续日志表明：

- `raw(type=2)` 仍长期保持明显重力分量，这本身不代表置零失败。
- `external(type=3)` 已接近 `0`，说明 payload 补偿与外力显示链路基本生效。

### 3. “红灯即刻触发”问题已被部分绕开

早期方案在导纳 / 恒力柔顺配置后，一旦发送运动指令，机械臂会颤抖一下后立刻红灯。

收缩为“到当前位姿的零位移触发”后，至少已经出现过一种状态：

- 不再立即红灯。
- 脚本能进入保持阶段并持续打印 TCP 与力传感读数。

这说明当前链路已经从“立即崩溃”推进到“可持续保持，但行为不符合目标”。

## 当前未解决问题

### 1. 机械臂仍然基本推不动

虽然已经能够进入恒力柔顺保持态，但手推时仍明显偏硬，不满足目标中的“人手阻挡时柔顺响应”。

### 2. 存在慢漂

当前保持阶段可观察到 TCP 缓慢向 `z+`、`y-` 方向漂移。此时 `external(type=3)` 仍接近零，说明问题更像是当前恒力柔顺配置 / 模式本身的行为，而不只是简单的未置零。

### 3. 现路线尚未达到最终验收目标

目标是“运动中或保持时，人工阻挡能柔顺应对而不红灯”。截至今天，现有最小脚本只能做到：

- payload 识别、写回、置零流程基本跑通。
- 某些配置下不再立即红灯。
- 但柔顺性不足，且存在慢漂。

因此，本轮方案仍未通过最终测试标准。

## 当前判断

- `raw(type=2)` 不能用来判断是否已正确置零，`external(type=3)` 才更接近用户真正关心的外力表现。
- 本轮问题的主因已经不再是“Python 参数类型错误”或“payload 完全没写进去”。
- 当前更像是：
  - 官方 `constant force compliance` 的这条触发路径，并不直接等价于“可自由手推的高柔顺示教 / 伺服柔顺”。
  - 六轴同时开启后的零位移恒力柔顺，在这台真机上表现为“偏硬 + 慢漂”，与目标手感不一致。

## 下次建议

- 不再围绕当前“零位移触发恒力柔顺”路线继续细调小参数。
- 优先重新核实官方文档中以下几类模式与适用场景的边界：
  - `constant force compliance`
  - `speed compliance`
  - `enable_admittance_ctrl` / 工具拖拽示教
  - servo 类接口下的柔顺 / 力控能力
- 如果目标始终是“运行后可直接用手推，并在阻挡时柔顺响应”，下一轮更应验证“servo / speed compliance 路线是否才是正确控制链”。
