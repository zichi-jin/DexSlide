# DexAlign 2.0

DexAlign 2.0 是 DexSlide 当前使用的新一版离线个体化标定方案。

这版方案的核心目标是把 3 类问题拆开做，而不是继续把它们硬塞进同一个联合点对点优化里：

1. 手掌几何朝向。
2. 手套关节角到模型自由度的映射。
3. 各骨段长度和 `T_marker2hand` 平移。

当前仓库里的采集脚本与优化入口已经切到这版方案。本文档同时承担两件事：

1. 说明 DexAlign 2.0 的设计动机与数学建模。
2. 约束后续代码继续沿这条三步路线演进。

## 一、设计动机

旧版 DexAlign 的主要问题是：

1. 直接用 RGB-D `MediaPipe` 表面点去拟合内部骨架点，观测模型错配明显。
2. 手掌朝向、关节角校准、长度标定和 `marker2hand` 外参在一个目标函数里强耦合，数值很不干净。
3. 拇指根部、手腕、掌面点误差尤其大，导致“全量联合优化”很容易学出补偿解，而不是真正有解释性的参数。

DexAlign 2.0 的思路是：

1. 先只拟合掌面 `5` 个基点相对 wrist 的方向，不碰长度。
2. 再只用骨段方向去校 `20` 个关节角通道的线性映射。
3. 最后在方向固定的前提下，再拟合长度和 `T_marker2hand` 的平移。

这样可以把“旋转问题”和“长度问题”拆开，减少互相吞误差。

## 二、基本约束

### 1. 坐标系与符号

本文档统一使用：

- `M`：marker body 坐标系。
- `H`：hand root 坐标系。
- `C_t`：第 `t` 帧观测坐标系，默认是相机系。

记：

- `^C_t T_M`：第 `t` 帧 marker 在相机系下的位姿。
- `^M T_H^0`：来自 `marker2wrist.json` 的固定初始 `marker2hand` 外参。
- `R_MH^0`：`^M T_H^0` 的旋转部分。
- `t_MH`：`^M T_H` 的平移部分。

### 2. 关键约定

这版方案固定以下前提：

1. `R_MH^0` 全程固定，不参与优化。
2. 只有 `t_MH = [tx, ty, tz]` 会在第三步参与优化。
3. 关键点数量固定为 `21`。
4. 长度单位统一为 `mm`。
5. 拇指 `CMC` 插补整条线彻底移除，不再引入额外 `thumb_cmc` 或线性牵连自由度。
6. 数据采集仍保留人工开关；交互目标简化为仅保留 `SPACE` 一个开关键。

### 3. 手掌五个 base 点

本文档中的“五个 base 点”固定指：

1. `thumb_base`
2. `index_mcp`
3. `middle_mcp`
4. `ring_mcp`
5. `pinky_mcp`

也就是对 wrist 建立 `5` 条射线：

`wrist -> thumb_base / index_mcp / middle_mcp / ring_mcp / pinky_mcp`

### 4. 当前阶段不再参考 `retargeting/` 目录中的废弃逻辑

DexAlign 2.0 只讨论当前运行时手模型的几何语义，不把历史 `retargeting/` 目录里的半成品实现当作设计依据。

## 三、输入与输出

### Step 0：初值

先取得两类初值：

1. `L_0`：初始手骨架。
2. `^M T_H^0`：初始 `marker2hand` 外参。

这两个量都来自现有资产：

- `L_0` 来自当前 `skeleton.json`
- `^M T_H^0` 来自当前 `left_marker2wrist.json` 中的 `initial_guess`

在 DexAlign 2.0 中：

1. `R_MH^0` 从头到尾固定。
2. `t_MH^0` 只是第三步的优化初值。

### 最终输出

DexAlign 2.0 最终产出三类结果：

1. `L_2`：长度完成对齐后的个体化手骨架。
2. `t_MH`：最终的 `marker2hand` 平移。
3. `w_q`：`20` 个关节通道到模型自由度的线性映射。

其中最终外参可写成：

`^M T_H = (R_MH^0, t_MH)`

### 落地输出契约

后续代码切换到 DexAlign 2.0 时，最终输出接口必须保持兼容，原因是主线结果查看脚本已经会消费这套产物。

固定约束如下：

1. session 目录仍落在 `assets/calibration/dexalign/<session_id>/`
2. 例如：`assets/calibration/dexalign/test_left_001/`
3. 最终结果文件名保持不变，至少包括：
   - `optimized_skeleton.json`
   - `optimized_marker2hand.json`
   - `optimization_report.json`

这意味着：

1. 即使内部实现切成 `Step 1 / Step 2 / Step 3`
2. 即使新增 `S1 / S2` 中间数据集或阶段性缓存
3. 对外暴露给主线脚本的最终 session 目录结构和结果命名也不能变

## 四、第一步：手掌形状

### 1. 数据集 `S1`

采集方式：

1. 只穿戴手套背板。
2. 不戴关节指环。
3. 没有关节角输入。
4. 每帧有 `^C_t T_M` 和 `21x3` 的 `MediaPipe` 3D 点。

记这批数据为 `S1`。

### 2. 这一阶段的目标

第一步只做一件事：

拟合 wrist 到五个 base 点的 `5` 条方向向量。

这一阶段：

1. 不优化任何长度。
2. 不优化 `R_MH`。
3. 不优化 `t_MH`。
4. 不做拇指 `CMC` 插补。

### 3. 如何把观测变到固定 hand frame

因为 `R_MH^0` 固定，所以每帧的 hand 朝向是已知的。

对每一帧 `t`，先取：

`R_CH(t) = R_CM(t) * R_MH^0`

再把观测点变到当前固定 hand frame 下：

`p_H_obs(t, i) = R_HC(t) * ( p_C_obs(t, i) - p_C_obs(t, wrist) )`

这里：

1. 只需要旋转，不需要绝对平移。
2. 用 wrist 做原点，是为了只关心 base 点相对 wrist 的朝向。

### 4. 观测量

对每帧、每个 base 点，计算单位方向：

`u_i_obs(t) = normalize( p_H_obs(t, i) )`

其中 `i` 取 `5` 个 base 点。

### 5. 优化变量

第一步的优化变量是 `5` 个单位方向：

`u_thumb, u_index, u_middle, u_ring, u_pinky`

它们的初值来自 `L_0` 中 palm 上对应的 `wrist -> base` 方向。

### 6. 目标函数

第一步推荐直接做方向拟合，例如：

`min Σ_t Σ_i || u_i - u_i_obs(t) ||^2`

实现时可以：

1. 先对 `u_i_obs(t)` 做 robust 平均。
2. 再投影回单位球。
3. 或直接做带单位范数约束的最小二乘。

### 7. 第一步输出 `L_1`

第一步结束后，不直接输出“裸方向”，而是要回写成 palm 基点坐标。

做法是：

1. 保留 `L_0` 中每个 `wrist -> base` 的模长 `r_i^0`
2. 用第一步学到的方向 `u_i`
3. 回写成：

`p_i^1 = r_i^0 * u_i`

也就是说：

1. 第一阶段只改 base 点朝向。
2. wrist 到各 base 的长度先沿用 `L_0`。

由此得到 `L_1`。

## 五、第二步：关节角校准

### 1. 数据集 `S2`

采集方式：

1. 穿戴完整手套。
2. 包括背板和指套。
3. 每帧有 `^C_t T_M`
4. 每帧有 `q_t ∈ R^20`
5. 每帧有 `21x3` 的 `MediaPipe` 3D 点

记这批数据为 `S2`。

### 2. 这一阶段的目标

第二步只拟合：

`20` 个关节通道到模型自由度的线性映射

记为：

`q_hat_j = a_j * q_j + b_j,  j = 1..20`

因此待优化参数是：

`w_q = { (a_j, b_j) }_(j=1..20 )`

总共 `20 * 2` 个参数，不是 `15 * 2`。

### 3. 为什么这一阶段只看方向

这一步不看点位，不看长度，只看 `15` 根骨段方向：

1. thumb：`3` 段
2. index：`3` 段
3. middle：`3` 段
4. ring：`3` 段
5. pinky：`3` 段

合计 `15` 段。

这样做的原因是：

1. 方向对表面点与骨架点的系统偏移更鲁棒。
2. 可以先把角度映射和长度问题拆开。

### 4. 观测方向如何计算

对 `S2` 的每一帧，先利用固定外参：

`^C_t T_H^0 = ^C_t T_M * ^M T_H^0`

把 `MediaPipe` 关键点变到固定 hand frame：

`p_H_obs(t, i) = ^H T_C(t) * p_C_obs(t, i)`

然后用相邻关键点相减并单位化，得到 `15` 根观测骨段方向：

`d_k_obs(t) = normalize( p_H_obs(t, child_k) - p_H_obs(t, parent_k) )`

### 5. 预测方向如何计算

给定 `L_1` 和 `q_hat`，只重建当前帧 `15` 根骨段的方向：

`d_k_pred(t; L_1, w_q)`

这一步不需要先关心绝对点位是否对齐。

### 6. 第二步目标函数

第二步建议优化：

`min Σ_t Σ_k || d_k_pred(t) - d_k_obs(t) ||^2 + λ_a Σ_j (a_j - 1)^2 + λ_b Σ_j b_j^2`

其中：

1. 第一项是 `15` 根骨段方向残差。
2. 第二项和第三项是弱正则。

正则的目的很明确：

1. `a_j` 拉向 `1`
2. `b_j` 拉向 `0`

避免某些关节在 `S2` 中激励不足时漂掉。

### 7. 第二步输出

第二步输出：

`w_q = { (a_j, b_j) }_(j=1..20 )`

到这一步为止，我们有：

1. `L_1`
2. 固定的 `R_MH^0`
3. `w_q`

## 六、第三步：长度对齐

### 1. 这一阶段的数据

第三步不单独采新数据，直接复用：

1. `S1` 中的 `T_marker` 和 wrist 观测
2. `S2` 中的全部数据

### 2. 待优化量

第三步默认只优化两类量：

1. `L_1` 中所有长度值
2. `t_MH = [tx, ty, tz]`

实验性 flag `--optimize-thumb-base-rx` 开启后，额外优化一个 `thumb_base_rx`。它不是自由的 `thumb_xyz`：`wrist -> thumb_base` 仍使用第一步得到的方向作为零位，只允许该方向严格绕 hand frame 的 x 轴旋转。相同的旋转会同步作用于 thumb 的 pp/ip/dp 局部 frame，避免只移动 base 点却不带动后续运动平面。

这里的“所有长度值”包括：

1. wrist 到 `5` 个 base 点的长度
2. thumb 的 `3` 段长度
3. 四指各自的 `3` 段长度

默认情况下，方向在这一步里固定：

1. palm 的 `5` 个 base 朝向固定为第一步结果
2. finger segments 的逐帧方向固定为第二步得到的 `w_q` 所重建出的方向

开启 `--optimize-thumb-base-rx` 时，只有 thumb base 方向及整条 thumb 局部 frame 可以围绕 x 轴共同转动；其余四指方向仍固定，Step 1 和 Step 2 的求解过程不变。

### 3. `t_MH` 的观测量

因为 `R_MH^0` 固定，而 hand root 定义在 wrist，所以每帧都可以从 marker 和 wrist 观测反推出一个平移样本：

`t_MH_obs(t) = R_CM(t)^T * ( p_C_obs(t, wrist) - t_CM(t) )`

其中：

1. `R_CM(t)` 和 `t_CM(t)` 来自 `^C_t T_M`
2. `p_C_obs(t, wrist)` 来自 `MediaPipe + depth`

这个量可从 `S1` 和 `S2` 中都提取出来。

### 4. 预测关键点如何构造

给定：

1. 第一步的 palm base 方向
2. 第二步的 `w_q`
3. 第三步正在优化的各段长度
4. 正在优化的 `t_MH`

就可以逐帧构造 hand frame 下的预测关键点：

`p_H_pred(t)`

再利用固定旋转和待优化平移变回相机系：

`p_C_pred(t) = ^C_t T_M * (R_MH^0, t_MH) * p_H_pred(t)`

### 5. 第三步目标函数

第三步建议联合使用两类残差：

1. 关键点点位残差
2. `t_MH` 平移残差

可写成：

`min Σ_t Σ_i w_ti || p_C_pred(t, i) - p_C_obs(t, i) ||^2 + λ_t Σ_t || t_MH - t_MH_obs(t) ||^2`

解释如下：

1. 第一项让重建关键点逼近 `S2` 的观测。
2. 第二项利用 `S1 + S2` 中由 marker 和 wrist 直接反推出的 `t_MH` 样本，稳定平移估计。

### 6. 第三步输出

第三步结束后，得到：

1. `L_2`
2. `t_MH`

最终结果是：

1. 个体化骨架 `L_2`
2. 固定旋转 + 优化平移组成的 `^M T_H`
3. 关节角映射 `w_q`

## 七、数据采集规范

推荐的离线数据组织形式是：

1. `S1` 和 `S2` 同属一个 session
2. 都放在 `assets/calibration/dexalign/<session_id>/` 下
3. 可分别保存为 `dataset_s1.*` 和 `dataset_s2.*`

优化器内部不会把 `S1` 和 `S2` 当作两条不同的求解分支，而是先把全部帧拼成统一帧池，再按每帧是否具备关节角、marker pose、wrist / palm keypoints 等模态决定它能参与哪一步。

这样既不破坏最终输出契约，也能明确区分“只戴背板”和“完整佩戴”两类采集。

### 1. `S1` 采集目的

`S1` 只服务于第一步和第三步，不需要关节角：

1. 稳定观察掌面五个 base 点相对 wrist 的方向。
2. 提取 `t_MH_obs(t)` 的平移样本。

### 2. `S2` 采集目的

`S2` 服务于第二步和第三步：

1. 用于校 `20` 个关节通道的 `a_j / b_j`
2. 用于在固定方向下做长度对齐

### 3. 人工采集开关保留

采集脚本里的人工开关功能保留，不回退成“脚本一运行就无差别录制”。

交互目标简化为：

- `SPACE`：采集开 / 关

也就是说：

1. 用户先在实时画面里看观测质量。
2. 摆到想录的关键姿态。
3. 再用 `SPACE` 放行或暂停。

## 八、这版方案与旧版的关键区别

DexAlign 2.0 和旧版方案的本质区别有 5 条：

1. 不再做一次性全量联合优化。
2. `R_MH` 固定，只在第三步优化 `t_MH`。
3. 拇指 `CMC` 插补整条线删除。
4. 先校方向，再校长度。
5. 第二步只校 `20` 个关节通道到自由度的线性映射，不直接碰点位长度。

## 九、实现落地时必须遵守的边界

后续开始改代码时，必须遵守下面这些边界：

1. 采集脚本的人工开关保留。
2. 采集交互简化为仅 `SPACE` 一个开关键。
3. Step 1 / Step 2 / Step 3 分开实现，不回到旧的一步联合优化。
4. `R_MH` 固定为 `left_marker2wrist.json` 中的 `initial_guess` 旋转，不参与优化。
5. 第二步所有观测都先变到固定 hand frame，再算骨段方向。
6. 第二步参数维度固定为 `20 * 2`。
7. 第一步输出 palm 点坐标，不能只输出方向向量。

## 十、当前结论

截至 `2026-07-22`，DexAlign 的新路线已经明确为：

1. `S1` 学 palm `5` 条 base 射线方向。
2. `S2` 学 `20` 个关节角通道的线性校准。
3. 再用 `S1 + S2` 学全部长度和 `T_marker2hand` 平移。

经文档确认后，代码实现应严格按这条路线切换。
